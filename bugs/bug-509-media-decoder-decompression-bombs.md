# bug-509: canvas/audio media decoders have no size caps — PNG/inflate/glyph/cmap/MML decompression bombs (DEC-50..55)

Last updated: 2026-09-03
Effort: medium (3h–1d)
Severity: HIGH
Class: security (denial of service — memory/CPU exhaustion on untrusted media)

Status: Open (found in audit-3, Surface 5 DEC-50/51/52/53/54/55; agent-demonstrated with crafted files and measured RSS/wall time)

Regression Test: fixtures asserting an oversized IHDR / inflate output / glyph raster / cmap12 numGroups / MML repeat is rejected in bounded time and memory.

## Summary

Every untrusted-media decoder reachable from a compiled MFBASIC program
(`canvas::loadImage`, `canvas::loadFont`, `audio::play`/`render`) lacks a cap on
the size it derives from the file, so a tiny hostile input forces multi-GB
allocation or minutes of CPU for one image/glyph/tune. These decoders are written
in MFBASIC (reads go through `collections::getOr`, integer `*` traps on overflow),
so there is **no memory corruption** — the class is uniformly a decompression /
amplification bomb.

| ID | Sev | What | Location | Demonstrated |
|---|---|---|---|---|
| DEC-50 | HIGH | PNG `width*height*4` allocated from IHDR with no max, before the data-present check | `canvas/helper_png.rs:397-405` | 69 B → 4.95 GB |
| DEC-51 | HIGH | inflate has no output cap (zlib bomb); decode reports success | `canvas/helper_inflate.rs:291-292,401-402` | 389 KB → 25 GB |
| DEC-53 | HIGH | glyph raster `w*h` unbounded from font `unitsPerEm`/coords; bypasses the 1 MiB budget | `canvas/helper_glyph_cache.rs:174-184` | 2-byte font mutation → 62.7 s / 7.57 GB for one letter |
| DEC-54 | HIGH | `cmap` format 12 `numGroups` is a raw u32 driving an unbounded scan | `canvas/helper_font.rs:203-205` | 583 s CPU to draw one char |
| DEC-55 | HIGH | MML `{ … }<count>` repeat count unbounded and nests multiplicatively | `audio/helper_mml_expand.rs:34-56` | 15-char tune → 38 GB |
| DEC-52 | MED | `__canvas_pngSlice` copies the accumulator per chunk → quadratic + arena-leaking multi-IDAT | `canvas/helper_png.rs:56-57,365-369` | 400 KB → 2.47 GB |

Enablers (LOW, filed here for context): DEC-56 (font table offsets never checked
against the file; `length` never read), DEC-57 (PNG CRC / zlib Adler never
verified), DEC-58 (inflate accepts over-subscribed Huffman trees), DEC-59 (glyph
cache key truncates gid to 16 bits), DEC-60 (`audio::render` `noteFrames` unbounded).

## Reproduction

`spikes/audit-3/DEC-50`, `DEC-51`, `DEC-55` (crafted inputs generated by
`spikes/audit-3/gen/mk*.py`; DEC-50/53/54 run in `app::Mode.Canvas`). Agent
measured the RSS/CPU above. Positive checks that the *usual* memory-safety suspects
are handled were verified (palette index bounds, bit-depth/colour-type table,
chunk-length-vs-file, stored-block LEN/NLEN, inflate distance-vs-produced, invalid
length/dist symbols, Adam7 pass-0, composite-glyph recursion disabled).

## Best fix

Add a hard maximum to every file-derived size before it is allocated or scanned:
a maximum image dimension / pixel count (DEC-50), an inflate output cap and ratio
limit (DEC-51), a glyph raster dimension cap (DEC-53), a `cmap12 numGroups` cap
bounded by the table length (DEC-54), an MML expansion cap on repeat count and
nesting product (DEC-55), and an incremental (non-quadratic) IDAT accumulator
(DEC-52). Reject past the cap with `ErrBadImageFile` / the audio equivalent.
Read and honor the font table `length` fields (DEC-56) so offsets are validated.

## Non-goals

No MFBASIC surface change; keep decoding of legitimate assets within the caps
(the caps must be generous enough for real fonts/images); the caps are the whole
fix — do not attempt to make the decoders faster.

## Prior art

None — the canvas GPU/decoder path postdates audit-2 and had no prior security
coverage (searched `png`, `inflate`, `glyph`, `cmap`, `mml`, `bomb`, `cap`).
