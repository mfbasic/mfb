### 1. "sets every colour channel to the colour's relative luminance" reads as byte = luminance, which the binary does not do
UNIT:      man-page:color/grayscale
CLAIM:     "grayscale sets every colour channel to the colour's relative luminance, so the result is a neutral grey that looks as bright as the original did."
VERDICT:   misleading
EVIDENCE:  `src/codegen/builtins/color/func_grayscale.rs:BODY` computes `lum = color::fromLinear((2126*r + 7152*g + 722*b) / 10000)` on `toLinear` channels, i.e. the channel is the sRGB *encoding* of the luminance, not the luminance scaled to a byte. Probe (`/tmp/plan-125-scratch/A-recheck-iter2/man-page-color-grayscale/probe.mfb`, built with `mfb build -q p_probe`): `color::luminance(rgb(0,255,0))` prints `0.72`, yet example 1 prints `#dcdcdc` (220), not `round(0.7152*255) = 182 = #b6b6b6`. A reader taking the sentence literally predicts the wrong grey by 38 steps. The probe also confirms the *intent* is right: `luminance(grayscale(green))` prints `0.72`, equal to the original.
SUGGESTED: "grayscale returns the grey whose relative luminance equals the colour's: the three channels are set to the sRGB byte whose linear-light value is that luminance, so the result looks as bright as the original did. (It is not luminance × 255 — a byte encodes gamma-compressed sRGB, not linear light.)"
