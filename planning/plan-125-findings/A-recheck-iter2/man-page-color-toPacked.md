### 1. Byte-order example prints decimal while its comment promises hex
UNIT:      man-page:color/toPacked
CLAIM:     "' red 0x12, green 0x34, blue 0x56, alpha 0x78 -> 0x78123456" (the comment in the first example, introduced as "The byte order, spelled out:")
VERDICT:   misleading
EVIDENCE:  Built the example verbatim as `/tmp/plan-125-scratch/A-recheck-iter2/man-page-color-toPacked/p_ex1` with `mfb build -q`; it compiles and prints `2014458966`. That is 0x78123456, but nothing on the page says so, and there is no integer-to-hex builtin to show it (`grep -rn 'name: "toHex"' src/codegen/builtins/` finds only `color::toHex`, which takes a `Color`). The example is billed as spelling out the byte order, yet the reader cannot see the bytes in what it prints and has to convert the decimal by hand to confirm the claim.
SUGGESTED: Change the comment to `' red 0x12, green 0x34, blue 0x56, alpha 0x78 -> 0x78123456, printed as 2014458966`, or follow the print with `io::print(color::toHexAlpha(color::fromPacked(color::toPacked(c))))` so the hex text form appears alongside the integer.

Everything else on the page checked out against the binary. Probe `p_edge` (same directory, built the same way) printed: opaque white `4294967295` and transparent black `0` (range bounds and "never negative"), opaque black `4278190080` (0xFF000000, alpha in the top byte), `color::Color[1, 2, 3, 4]` → `67174915` (0x04010203, confirming A-R-G-B byte order on a literal as well as on `rgba`), the masked 0xRRGGBB value fed back through `fromPacked` → `51 102 204 0` (the "fully transparent colour" sentence), the source colour's `red` still `10` after packing (no mutation), and `color::red` → `4294901760` (0xFFFF0000). The second and third page examples printed `10 20 30 40` and `3368652` (0x3366CC) as the page implies. The empty Errors table is correct: the body in `src/codegen/builtins/color/func_to_packed.rs:BODY` shifts by the constants 24/16/8 only, so the `bits::sl` `ErrInvalidArgument` listed for it in `exception_tables.rs:UNREACHABLE_VIA_CALLEE` cannot fire. "The same one everywhere in MFBASIC" holds for every program-visible surface: `astrings` attributes carry 0xAARRGGBB (`src/docs/spec/stdlib/15_astrings.md`), and the only opposite-order slot is the term backend's private state that no program can read (`src/docs/spec/app/04_term-backend.md`). No banned memory vocabulary and no compiler-model sentence appears on the page.
