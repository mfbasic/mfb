### 1. Closing paragraph: the runtime already restores the terminal on every exit path
UNIT:      man-page:term/off
CLAIM:     "Because the alternate screen and the terminal's line discipline are both process state, a program that enters TUI mode should reach `term::off` on every exit path — including its error paths — or leave the user's terminal in single-key mode on the alternate screen."
VERDICT:   wrong
EVIDENCE:  The shared process teardown calls `term::off` itself whenever the program imports `term`: `lower_shutdown(auto_term_off, …)` in `src/codegen/os/process/process_lifecycle.rs` branches to `_mfb_rt_term_term_off` when `auto_term_off` is set, and `src/codegen/engine/builder/mod.rs:1969` passes `uses_term` for that flag. Three exit paths reach it: the normal return and the unhandled-error path both fall through `exit_label` to `bl _mfb_shutdown` (`src/codegen/engine/function/entry.rs:729`), and `lower_signal_handler` (same file as the teardown) runs it for SIGINT/SIGTERM. The spec already states this (`src/docs/spec/memory/08_program-startup.md:166`: "It restores the terminal when `term::` was active"). Probes under `/tmp/plan-125-scratch/D-phase3/man-page-term-off`:
  - `p_err` (`term::on()` then `MUT r AS Integer = 10 / z` with `z = 0`, never reaching `term::off`): exit 255, stderr `Error: 7-705-0002`, and stdout ends `\x1b[?25h \x1b[?1049l \x1b[0m` (`od -c err.out | tail -3`), i.e. the cursor-show, leave-alternate-screen and attribute-reset sequence was written by the runtime.
  - `p_sig` (`term::on()` then `os::sleep(5000)`), sent SIGTERM after 1 s: exit 143 and stdout ends with the same three-sequence restore (`od -c sig.out | tail -3`).
  So a program that never reaches `term::off` on an error path does NOT leave the terminal on the alternate screen. Only a hard kill (SIGKILL) or a crash the runtime cannot intercept would.
SUGGESTED: "You do not have to reach `term::off` before the program ends: when a program that uses `term::` exits — by returning from `main`, by an unhandled error, or on Ctrl-C/SIGTERM — the runtime calls `term::off` for it, so the terminal is restored. Call it explicitly when you want to print ordinary output after the TUI part of the program, or to leave and re-enter TUI mode. A `kill -9` or a crash the runtime cannot intercept still leaves the terminal on the alternate screen in single-key mode; `reset` at the shell recovers it."

### 2. Steps 1–3 describe the console backend only; the `--app` window behaves differently
UNIT:      man-page:term/off
CLAIM:     "When TUI mode is on, the teardown runs in this order. … 3. The terminal is restored: the cursor is made visible, the alternate screen is left so the user's previous shell contents reappear, and the terminal's colour and attribute state is reset so ordinary output that follows is drawn normally."
VERDICT:   incomplete
EVIDENCE:  The first paragraph claims parity "on every backend, in a terminal and in an `mfb build --app` window alike", but only the gating is shared. The console emitter `emit_off` (`src/codegen/term/core/term.rs:449`) does sync → cooked termios restore → `ESC_OFF` (`\x1b[?25h\x1b[?1049l\x1b[0m`, line 49) → clear active → free grid, matching steps 1–4. The app emitter `emit_app_term_off_helper` (`src/target/macos_aarch64/app/app_io.rs:435`) instead forces the term view to `display`, swaps the window's content view back to the transcript scroll view, makes the transcript first responder, and sets the window input mode back to line-echo. There is no cursor, alternate screen, or colour reset there because there is no terminal. The page never tells the developer that in a window "restore" means the transcript view comes back and typing returns to line input. UNVERIFIED at runtime: the sandbox cannot open an app window; read from source only.
SUGGESTED: After step 4 add: "In an `mfb build --app` window there is no cursor or alternate screen to restore: step 3 instead swaps the window back to its scrolling text view, which regains keyboard focus, and typing returns to line input. Steps 1, 2 and 4 are the same."
