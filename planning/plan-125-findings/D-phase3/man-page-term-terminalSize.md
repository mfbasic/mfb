### 2. In macOS app mode an allocation failure raises ErrUnsupported, not ErrOutOfMemory
UNIT:      man-page:term/terminalSize
CLAIM:     "Besides ErrUnsupported it can raise ErrOutOfMemory while producing its result."
VERDICT:   misleading
EVIDENCE:  `src/target/macos_aarch64/app/app_io.rs` `emit_app_terminal_size`: after `asm.call_internal(ARENA_ALLOC_SYMBOL)` the failure branch is `abi::branch_ne(&unsupported)`, and the `unsupported` label loads `runtime_error_emission("ErrUnsupported")`. There is no `ErrOutOfMemory` emission anywhere in that function. Only the console path (`src/codegen/term/core/term.rs` `emit_terminal_size`, label `alloc_error`) raises `ErrOutOfMemory`. The page's app-mode paragraph lists only "TUI mode is off or no view is attached" as the `ErrUnsupported` conditions, so a reader trapping on `ErrOutOfMemory` in an `--app` build on macOS never sees it. UNVERIFIED by probe (cannot exhaust the arena in a sandbox); code-read only. I did not check the GTK or Windows app emitters for the same detail.
SUGGESTED: In the console paragraph: "Besides ErrUnsupported it can raise ErrOutOfMemory while producing its result." → keep, and add to the app-mode paragraph: "In app mode a failure to produce the result also raises ErrUnsupported; ErrOutOfMemory is a console-build error only."
