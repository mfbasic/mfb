### 1. `child` is accepted under the named argument `parent`
UNIT:      man-page:fs/isWithin
CLAIM:     "The path tested for containment (also accepted as `parent`)."
VERDICT:   misleading
EVIDENCE:  `src/codegen/builtins/fs/func_is_within.rs:register` — the `child` Parameter has `aliases: &["parent"]`, introduced unchanged by commit 73374e779 (`git log -S'aliases: &["parent"]'`). Probe `/tmp/plan-125-scratch/D-phase5-current/man-page-fs-isWithin/p-edge/src/main.mfb` line `fs::isWithin(path := t & "/a", parent := t & "/a/b")` compiled and printed `named alias: TRUE`, so `parent := …` really binds the *child* (the nested path), the opposite of what the word means. Neither `fs::openWithin` nor `fs::canonicalPath` carries any alias (`grep -n aliases src/codegen/builtins/fs/func_open_within.rs src/codegen/builtins/fs/func_canonical_path.rs` → all `&[]`), and the spec never names a `parent` argument for `isWithin` (`grep -rn parent src/docs/spec/stdlib/21_fs-host-errors.md` → nothing). The sentence is true of the binary, but the thing it truthfully documents is a trap: a developer who writes `isWithin(parent := root, path := file)` gets the roles swapped silently and the call still compiles. This is a descriptor bug, not a prose fix (§0: a wrong derived surface is code).
SUGGESTED: Drop the `parent` alias from `child` in the descriptor (and consider dropping `path` from `base`, since `path` naturally reads as the thing being tested, not the container). The parameter description then becomes: "The path tested for containment. Interpreted as UTF-8 bytes; may be absolute or relative to the current working directory. Every named component, including the last, must exist. Must be non-empty and free of embedded NUL bytes." If the alias must stay for compatibility, the description must warn: "also accepted under the legacy name `parent`, which names the *tested* path, not the container".

Everything else on the page verified against the binary at HEAD. Probes under `/tmp/plan-125-scratch/D-phase5-current/man-page-fs-isWithin` (each built as an `mfb init` project with `mfb build -q`): the three page examples printed `inside` / `its parent is outside`, `TRUE`, and `TRUE` / `FALSE` exactly as the page implies. The edge probe printed `root: TRUE` (base `/`), `symlink into: TRUE` (a link under `c/` resolving into `a/`), `symlink out: FALSE` (a link under `a/` to `/etc`), `dotdot: FALSE` (`a/b/../../c`), `trailing slash: TRUE`, `double slash: TRUE`, `file base: TRUE` (a file equal to itself), `relative: TRUE` (both relative to cwd). Error probes: empty `base` → `7-705-0002` ErrInvalidArgument; a String containing a NUL built with `encoding::formUrlDecode("%00")` → `7-705-0002`; a missing final component → `7-703-0001` ErrPathNotFound; a `chmod 000` directory on the way → `7-703-0003` ErrAccessDenied; a file used as a directory → `7-703-0002` ErrInvalidPath. Each matches the Errors paragraph and the shared mapping documented in `gen_shared.rs:emit_fs_host_error_mapping`. The Windows root/separator remark is UNVERIFIED (no Windows host); the lowering in `gen_canonical.rs:lower_fs_is_within_helper` selects byte 92 on Windows, consistent with the prose. No banned vocabulary and no borrow/ownership framing found in the rendered page.
