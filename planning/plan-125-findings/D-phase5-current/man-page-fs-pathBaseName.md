### 1. Backslash is never a separator, even on Windows — the page does not say so
UNIT:      man-page:fs/pathBaseName
CLAIM:     "The scan is byte-oriented (the separator is the single byte `47`), so UTF-8 file names are preserved unchanged and any embedded bytes are treated literally."
VERDICT:   incomplete
EVIDENCE:  `fs_path_base_name_window` in `src/codegen/builtins/fs/gen_path_builder.rs` compares only against immediate `47` (both in `emit_trailing_slash_trim` and the backward scan); the compiler ships a `win_x86_64` target (`ls src/target/`). Probe `/tmp/plan-125-scratch/D-phase5-current/man-page-fs-pathBaseName/p_probe` printed `[a\b] -> [a\b]`, so a Windows-style path comes back whole. The page only implies this through "the single byte 47", which a developer must decode; the sharp edge a Windows developer will hit is never stated in words, and no other `fs` page mentions it either (`mfb man fs | grep -i backslash` is empty).
SUGGESTED: "Only `/` is a separator. A backslash is an ordinary character even on Windows, so `"a\b"` is returned unchanged. The scan is byte-oriented, so UTF-8 file names are preserved unchanged."

Everything else on the page checked out. All five examples were built from fresh `mfb init` projects under the scratch directory with the P-125 release binary and printed `output.txt`, `bin`, `bin`, `output.txt`, `/`, matching the captions. The probe program covered `""`, `"/"`, `"//"`, `"///"`, `"a"`, `"a/"`, `"a///"`, `"/a"`, `"/a/"`, `"a//b"`, `"a/b/"`, `"."`, `".."`, `"a/.."`, `"dir/.hidden"`, `"é/ü"`, `"日本/語.txt"`, `"a/b "`, and `" /"`; every result agreed with the page's description of trailing-slash trimming, the lone-`/` rule, the empty-string rule, no-separator passthrough, literal `.`/`..`, and UTF-8 preservation. The single Errors row is consistent with the descriptor's `errors: vec!["ErrOutOfMemory"]` and the `raise_error_bare("ErrOutOfMemory")` in `emit_materialize_string_from_bytes`; the out-of-memory condition itself is UNVERIFIED by probe, since it cannot be triggered deliberately. No banned vocabulary and no borrow/ownership teaching appears on the page.
