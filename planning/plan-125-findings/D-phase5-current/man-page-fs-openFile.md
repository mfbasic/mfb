### 1. readWrite overwrites from the start of the file, and the page never says where a write lands
UNIT:      man-page:fs/openFile
CLAIM:     `"readWrite" opens the file for both reading and writing, creating it when it does not exist but preserving existing contents.`
VERDICT:   incomplete
EVIDENCE:  Probe `/tmp/plan-125-scratch/D-phase5-current/man-page-fs-openFile/rw/src/main.mfb`: file containing `hello world\n`, then `fs::openFile(p, "rw")`, `fs::writeAll(f, "XY")`, `fs::close(f)`, `io::print("[" & fs::readText(p) & "]")` printed `[XYllo world\n]`. Lowering: `gen_open.rs` comment `rw = O_RDWR|O_CREAT|O_CLOEXEC` (no `O_APPEND`, no `O_TRUNC`). "Preserving existing contents" is true only at open time; the first write overwrites bytes 0..n in place. A developer reaching for `"rw"` to add to a file (the sharp edge the page's own sibling mode, `"append"`, exists for) is not warned.
SUGGESTED: `"readWrite" opens the file for both reading and writing, creating it when it does not exist and leaving existing contents in place. Reading and writing both start at the beginning of the file, so the first write overwrites what is there byte for byte rather than adding to it; use "append" to add at the end, or fs::seek to choose a position.`

### 2. The NUL-byte justification is a host-API fact, not a developer fact
UNIT:      man-page:fs/openFile
CLAIM:     `The string must not be empty and must not contain an embedded NUL byte, because the host open call requires a NUL-terminated path.`
VERDICT:   out-of-scope
EVIDENCE:  `.ai/man-content.md` §1: "if a sentence only matters to someone reading compiler source, it does not belong on the page." The behaviour itself is verified (probe `probe/src/main.mfb`: path `F & "/pl\u{0}ain.txt"` → `77050002 Argument value is not valid for the requested operation.`), but the `because …` clause explains it through the C `open(2)` calling convention, which is exactly the mental model the standard keeps off the page. The same clause is duplicated on `fs::open`; this unit only covers `openFile`.
SUGGESTED: `The string must not be empty and must not contain a NUL byte; either raises ErrInvalidArgument.`

Everything else on the page checked out against the binary at HEAD. Audit trail for the no-finding sentences:

- **Examples**: all three extracted from the rendered page, built with `mfb init` + `mfb build`, and run. Example 1 exits 0 silently (nothing to print), example 2 prints `hello`, example 3 prints `first line` then `started`. All three remove their scratch directory. The first launch of the example-2 binary stalled at `_dyld_start` with zero CPU before any program code ran and later runs of the same binary completed normally, so that was a macOS first-launch stall, not the example.
- **Errors table and the error paragraph**, from the probe at `/tmp/plan-125-scratch/D-phase5-current/man-page-fs-openFile/probe/src/main.mfb` (fixtures under `fix/`): missing file in any mode → `77030001`; directory in `r`, `w`, `a`, `rw` and default mode → `77030002`; empty path, NUL path, `"Read"`, `""`, `"W"` → `77050002` and no file was created by the bad mode; missing parent in `r` and `w` → `77030001`; `chmod 000` file in `r` and `w` → `77030003`; symlink loop, 300-byte component, and file-used-as-directory in `r` and `w` → `77030002`. Fallback arm confirmed in `gen_shared.rs:emit_fs_host_error_mapping` with `FsFallback::ByAccess`: `ErrReadFailed` for the read-only flag set, else `ErrWriteFailed`.
- **Mode semantics**: `rw` and `a` create a missing file; `write` on an existing file leaves it empty; `readWrite` leaves `hi\n` intact at open; `r` through a symlink opens the target. `stat -f %Sp` on the three created files printed `-rw-------` under umask 022, matching the 0600 claim. Mode table in `gen_open.rs` lists exactly `r`, `read`, `w`, `write`, `rw`, `readWrite`, `a`, `append`, matched before the host call.
- **Scope-exit close**: probe `scope/src/main.mfb` opens a file inside a function with no `fs::close` and sleeps; `lsof -p` showed the file open during the function (count 1) and closed after it returned (count 0).
- **Vocabulary**: `grep -i -E` with the `scripts/man-census.sh --banned-list` alternation over the rendered page hits only the derived `Allocation failed.` message in the Errors table, which is the §4.4 carve-out. No borrow/ownership model is taught without a banned word: the only handle-lifetime sentence uses "closed when the binding … goes out of scope", which is the §4.3 prescribed phrasing.
- **Intro vs description**: distinct, one sentence, no trailing prose.
