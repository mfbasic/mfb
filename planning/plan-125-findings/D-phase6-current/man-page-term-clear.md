### 1. Windows `--app` left out of the "when does it appear" sentence
UNIT:      man-page:term/clear
CLAIM:     "In a terminal and in a macOS --app build the blanked screen appears when the program calls term::sync; a Linux --app build repaints from the clear itself."
VERDICT:   incomplete
EVIDENCE:  `src/target/win_x86_64/app/mod.rs:emit_term_clear` blacks the memDC with `PatBlt` (rop 66 = BLACKNESS) and its comment says "`clear_done` requests no repaint"; the window is presented by `emit_term_sync` (`"term.sync" => emit_term_sync` at mod.rs:3490). So Windows behaves like the terminal and macOS, but the sentence enumerates three of the four builds and leaves a Windows reader guessing which side it falls on. macOS confirmed: `src/target/macos_aarch64/app/app_io.rs:emit_app_clear` comment "no redraw, the repaint is present-driven". Linux confirmed: `src/target/linux_gtk/app_io.rs:emit_app_term_clear` calls `g_idle_add(TERM_REDRAW_IDLE_SYMBOL)`.
SUGGESTED: "In a terminal, and in a macOS or Windows --app build, the blanked screen appears when the program calls term::sync; a Linux --app build repaints from the clear itself."

### 2. The gating paragraph states the two gates in the wrong order for an `--app` build
UNIT:      man-page:term/clear
CLAIM:     "The call is gated: while TUI mode is off it does nothing. … In an mfb build --app program, term::clear — like every other term:: call — raises ErrWrongMode unless the program is in app::Mode.Console; see mfb man app."
VERDICT:   misleading
EVIDENCE:  `src/codegen/builtins/term/gen_shared.rs:lower_term_helper` calls `prepend_wrong_mode_gate(..., ModeRequirement::Console)` on the app helper body, i.e. the mode check runs *before* the per-platform TUI-active gate (`emit_term_active_gate` in `app_io.rs:emit_app_clear`, `emit_gtk_term_active_gate`, `emit_win_term_active_gate`). A reader of the first sentence will expect a `term::clear` in `app::Mode.None` or `Mode.Canvas` with TUI off to be a silent no-op; it raises `ErrWrongMode`. The page never says which check wins.
SUGGESTED: Reorder and make the precedence explicit: "In an mfb build --app program the mode check comes first: term::clear — like every other term:: call — raises ErrWrongMode unless the program is in app::Mode.Console, whether or not TUI mode is on; see mfb man app. Otherwise the call is gated on TUI mode: while it is off, term::clear does nothing."
