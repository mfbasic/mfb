### 1. "cannot fail" contradicts the Errors table it sits above
UNIT:      man-page:term/getUnderline
CLAIM:     "The call reads state only. It changes no term:: state, draws nothing, and cannot fail."
VERDICT:   misleading
EVIDENCE:  The derived Errors table lists ErrWrongMode, and `src/codegen/builtins/term/gen_shared.rs:lower_term_os_seam` prepends `prepend_wrong_mode_gate(.., ModeRequirement::Console, ..)` when `build_mode.is_app()`, so the call does fail (traps) in an `--app` build outside `app::Mode.Console`. The very next sentence on the page admits this. A reader who stops at "cannot fail" has been told something false; the qualifier belongs in the same sentence. (Not probed: an `--app` build needs a window and cannot run in this sandbox; the claim is verified by reading the gate, not by execution.)
SUGGESTED: "The call reads state only. It changes no term:: state and draws nothing. In a plain build it cannot fail; in an mfb build --app program it — like every other term:: call — raises ErrWrongMode unless the program is in app::Mode.Console; see mfb man app."

Everything else on the page checks out against the binary. Probe at /tmp/plan-125-scratch/D-phase6-current/man-page-term-getUnderline/probe/src/main.mfb (built with `mfb init probe && mfb build probe`, run with stdin from /dev/null) printed: before on FALSE; setUnderline(TRUE) while off then read FALSE (the setter is inert while off, `attributes.rs:emit_set_attr` gates on active); after on FALSE; after set TRUE TRUE; after set FALSE FALSE; set TRUE then a second term::on FALSE (`screen_mode.rs` writes `TERM_STATE_UNDERLINE_OFFSET = 0` on every on); set TRUE after second on TRUE; after off FALSE (`attributes.rs:emit_get_attr` inert branch returns 0); third on FALSE. Both page examples were built as projects and ran to exit 0; the second printed "plain" inside the alternate screen, as the page implies for a fresh term::on. The per-cell claim is backed by `draw.rs` loading bold/underline from state at draw time. No banned memory vocabulary and no borrow/ownership model is taught; "read directly" is the only faintly implementation-flavoured phrase and it does not require a compiler mental model.
