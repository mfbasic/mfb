### 1. "never fails" contradicts the Errors table on the same page
UNIT:      man-page:strings/stripSuffix
CLAIM:     "The function is total and never fails."
VERDICT:   misleading
EVIDENCE:  `src/codegen/builtins/strings/func_strip_suffix.rs` registers `errors: vec!["ErrOutOfMemory"]`, so the rendered page (`mfb man strings stripSuffix`) carries an Errors row for ErrOutOfMemory and, two paragraphs later, the sentence "ErrOutOfMemory means the program ran out of memory." The lowering (`gen_strip::lower_strings_strip` → `emit_materialize_string_from_bytes`) builds a fresh string on every path, including the unchanged one, so the out-of-memory condition is real on every call. A page cannot say "never fails" and list a raisable error.
SUGGESTED: "No input is rejected: an empty `value`, an empty `suffix`, a longer-than-`value` suffix and a non-matching suffix all return an equal string. The only error is `ErrOutOfMemory`, raised when the program has run out of memory."

### 2. "new String back, even on the unchanged path" teaches an identity model the language has no way to observe
UNIT:      man-page:strings/stripSuffix
CLAIM:     "Neither operand is modified, and you always get a new `String` back, even on the unchanged path."
VERDICT:   out-of-scope
EVIDENCE:  MFBASIC values are never shared (`.ai/man-content.md` §4.1: "two variables never share one"), so "new" versus "the same" String is a distinction with no developer-visible consequence; it is a claim about `emit_materialize_string_from_bytes` allocating on the unchanged path (`gen_strip.rs`), i.e. a compiler fact in §3's sense, and the §7 subtle failure: it invites the reader to wonder whether an unchanged result might alias its input. Probe (`p_probe`, lines 15–17 of probe.mfb): `LET s = "hello.txt"`, `LET t = strings::stripSuffix(s, ".txt")`, print `s & " " & t` → `hello.txt hello`. The developer-visible fact is only that `value` is unchanged. The parameter description already says it correctly ("Returned as an equal copy").
SUGGESTED: "`value` and `suffix` are not modified; the result is a separate String value, equal to `value` when nothing was stripped."
