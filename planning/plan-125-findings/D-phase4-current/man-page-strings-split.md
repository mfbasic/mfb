### 1. A delimiter can split a grapheme cluster; the page only rules out splitting a scalar
UNIT:      man-page:strings/split
CLAIM:     "Because both operands are well-formed UTF-8, a delimiter is only found where its complete byte sequence appears, so a split can never land mid-scalar."
VERDICT:   incomplete
EVIDENCE:  Probe `probe_graph.mfb`: `LET v AS String = "e\u{0301}x"` (one grapheme `é` written as e + combining acute, then `x`; `graphemesCount` prints 2). `strings::split(v, "\u{0301}")` returned 2 elements, `<e> bytes=1` and `<x> bytes=1`. The combining mark is a legal delimiter, the match lands inside the grapheme, and the accent is removed from the output. The sentence is true as written, but §2 of the standard requires "Unicode scalar vs. grapheme" to be stated explicitly, and the only sentence on the page that names the boundary stops at the scalar, leaving the reader to infer grapheme safety that does not exist. The lowering (`func_split.rs:lower`, byte-compare loop at `length_compare`/`write_compare`) does no grapheme check.
SUGGESTED: "Because both operands are well-formed UTF-8, a delimiter is only found where its complete byte sequence appears, so a split never lands inside a scalar value. It can land inside a grapheme: a delimiter that is a combining mark, such as `"\u{0301}"`, matches the mark after its base letter and leaves the base letter in one piece and the next character in the next, so the accent is removed from the output. To cut on user-perceived characters, use `strings::graphemes`."

### 2. ErrOutOfMemory is in the Errors table but has no condition in the prose
UNIT:      man-page:strings/split
CLAIM:     Errors table row "77010001 │ ErrOutOfMemory │ Allocation failed." with no corresponding sentence in Description.
VERDICT:   incomplete
EVIDENCE:  `mfb man strings split | grep -i memory` matches only the derived table row. The descriptor lists `errors: vec!["ErrInvalidArgument", "ErrOutOfMemory"]` and the lowering raises `ErrOutOfMemory` both when the result cannot be obtained and when the result size overflows (`size_overflow` label in `func_split.rs:lower`). §2 of the standard requires "every raisable error and the condition that raises it". The sibling `strings::graphemes` page does state it ("ErrOutOfMemory means the program ran out of memory.", `mfb man strings graphemes` line 53); `join`, `replace` and `count` do not, so this page is consistent with some siblings and not others.
SUGGESTED: Add after the ErrInvalidArgument paragraph: "`ErrOutOfMemory` is raised when the program cannot obtain room for the result list."

### 3. The `separator` alias is stated twice and never shows the call syntax
UNIT:      man-page:strings/split
CLAIM:     "delimiter is also accepted under the name separator." (Description, opening the join paragraph) and "Also accepted under the name separator." (Parameters table)
VERDICT:   incomplete
EVIDENCE:  Named arguments use `:=` (spec `language/06_functions.md` "Named args at call site: `greet("Ada", greeting := "Hi")`"). Probe `probe1.mfb` confirms both `strings::split("k=v", separator := "=")` and `strings::split("k=v", delimiter := "=")` compile and print `[2] <k> <v>`; a first attempt with `separator: "="` (the obvious guess) failed to parse with `MFB_PARSE_UNEXPECTED_TOKEN`. The page says the name is accepted but never shows how to use it, and the Description sentence is a verbatim repeat of the parameter cell that also sits as the first sentence of a paragraph about joining, where it is off-topic.
SUGGESTED: Drop the Description sentence and make the parameter cell carry the usage: "The separator to break `value` on. Must be non-empty. May be passed by name as `delimiter := ","` or `separator := ","`."

All other sentences verified true at HEAD. Examples: all three page examples compiled with `mfb build -q proj` and printed `3`/`b`, `4`/`1`, and `TRUE`/`a-b-c` as the page implies. Probe `probe1.mfb` confirmed `",a,,"` gives 4 elements `"" "a" "" ""`, `""` gives one `""`, a delimiter longer than value gives `["abc"]`, `"aaa"` on `"aa"` gives `["", "a"]` (non-overlapping, resume after match), `"ABC"` on `"b"` gives `["ABC"]` (no case folding), and `value` is unchanged after the call. `probe_empty.mfb` and `probe_count.mfb` both raised `7-705-0002 ErrInvalidArgument` for an empty delimiter, matching the "exactly as strings::count does" claim; `mfb man strings` does contain the cited "The empty needle" rule. `probe_astr.mfb` confirmed `strings::split(AttributedString, ",")` returns `List OF String` with 3 elements, and `probe_astr_empty.mfb` confirmed the empty-delimiter error is raised for the overload too (`is_tier_a_query` lists `strings.split`). `probe_regex.mfb` confirmed `regex::split` follows the same count+1 rule (`",a,,"` gives 4, `""` gives 1). No banned §4 vocabulary and no borrow/ownership model found on the rendered page.
