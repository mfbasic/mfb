### 1. Attributed overload: replacement text is unstyled, page implies spans simply follow the edit
UNIT:      man-page:strings/replace
CLAIM:     "`value` may also be an `AttributedString`: it returns an `AttributedString` whose text is transformed exactly as the `String` overload's and whose attribute spans are remapped by the same edit."
VERDICT:   incomplete
EVIDENCE:  Probe `/tmp/plan-125-scratch/D-phase4-current/man-page-strings-replace/p2.mfb` (built via `run.sh p2` with the P-125 release `mfb`): bold over scalars 1..3 of `"hello"`, then `strings::replace(a, "l", "xx")`, rendered through `astrings::toMarkdown`. Output: `h**ell**o` before, `h**e**xxxxo` after. A whole-string bold `"hello"` with `"ll"` deleted printed `**heo**`, and a no-match call printed `**hello**`. So the matched region's styling is dropped with the match and the inserted `new` text carries no attributes. The page says only that spans are "remapped by the same edit", which a reader naturally takes to mean bold `ell` becomes bold `exxxx`. It does not. The `astrings` overview states the rule ("text the call adds, such as replace's replacement … carries no" attributes), but this page is where a developer calling `replace` reads, and it omits the sharp edge.
SUGGESTED: "`value` may also be an `AttributedString`: the result is an `AttributedString` whose text is transformed exactly as the `String` overload's. Attributes on text that survives the edit stay with that text; the matched text's attributes go with it, and the inserted `new` text carries no attributes. When nothing matches, the result keeps every attribute of `value`."

### 2. `value` parameter does not say what an empty `value` does
UNIT:      man-page:strings/replace
CLAIM:     "The string to copy from, replacing matches as they are found."
VERDICT:   incomplete
EVIDENCE:  `.ai/man-content.md` §2 requires every parameter description to state "what happens at zero/empty/negative". Probe `p1.mfb` line `strings::replace("", "a", "x")` printed `empty value: []`, so an empty `value` is accepted and returns the empty string (no error). The description, and the Description section, say nothing about an empty `value`; the `old` and `new` descriptions do cover their empty cases, so this is the one parameter left unanswered. The sibling `strings::count` page says "May be empty" for its `value`.
SUGGESTED: "The string to copy from, replacing matches as they are found. May be empty, in which case the empty string is returned."

Everything else on the page checked true against the binary. Probe `p1.mfb` (same directory, run with `run.sh p1`) printed: `replace empty old: code=77050002 isInvalidArg=TRUE`, and `count empty`, `split empty`, `regex empty` all `code=77050002`, confirming the Errors table row and the three sibling-refusal sentences; `accent: x<U+0301> len=2 eq=TRUE` and `nfd-vs-nfc: e<U+0301>` (NFC `é` did not match NFD), confirming the byte-comparison, no-normalization and split-character sentences; `inputs after: hello l x result=hexxo` and `src=abc outv=abc!` confirming no argument is mutated and the no-match result is an independent copy; `aaa/aa->b: ba`, `a/a->aa: aa`, `old==new: aaa` confirming non-overlap and that a replacement is never re-examined; `astring: hexxo` confirming the `AttributedString` overload exists. The strings overview's "The empty needle" section exists and names replace, so the `mfb man strings` pointer resolves, and `mfb man collections replace` renders. All four page examples compiled and printed `hexxo`/`ba`, `xba`/`hi`, `no needle was supplied`, and `heqqo`, matching the page. No banned vocabulary and no compiler-model sentences were found; "independent of the one you passed in" is the sanctioned copy vocabulary from §4.1.
