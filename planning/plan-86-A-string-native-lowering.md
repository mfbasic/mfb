# plan-86-A — String-element native collection lowering

Sub-plan **A** of [plan-86](plan-86-benchmark-perf.md) (master: goals, scorecard, source logs,
measurement protocol). Split candidate; **partition + sortBy + sort + flatten landed**, the
nested-block/new-lowering tail is open.

**Covers (~11 P1 + 1 P3):** list (Dynamic) groupby (166), window (88), sortBy (61), sort_rand/asc/desc
(28.9/22.9/22.6), zip (25.6), flatten (24.6), partition (18.7), chunks (13.6), findLastIndex (11.1);
listchurn nested (12.3); list (Fixed) sort_rand (5.07). All min≈median ⇒ genuine, not arena.

## Root cause
plan-64's native list generics gate on `Integer|Float|Fixed|Money` (the monomorph item-type suffix), so
String falls to the interpreted `.mfb __collections_*` bodies; `sort`/`zip`/`flatten`/`findLastIndex` had
no native path at all. A String element is a block-relative offset into an inlined sub-block
(`[[records-inline-their-string-fields]]`), not a pointer, so native paths need a **data-region-aware
element move**, not an 8-byte word copy. Gates: `builder_values.rs` sortBy/window/groupBy/chunks/partition;
`.mfb` fallbacks in `src/builtins/collections_package.mfb`.

## Corrections
- **A1 sort/sortBy use an index-permutation gather, not an in-place String merge.** Building keys via native
  `transform` (correctly sizes the `n*8` Integer buffers; a `lower_reserved_list(String source)` sizes from
  the string bytes → would overflow) is what makes it work. Gotcha: the dispatch gate must guard only the
  *source* (args[0]) for re-eval; the keyFn is a `functionRef` (not Local/Const/Global/LocalRef), so gating
  on all args kept String sortBy on the `.mfb` path (measured ~no change until narrowed). Matching output
  did NOT prove native ran — only the 61→8 ms drop did.
- **partition is a G2-class result, not a G1 clear** (Partition-record inline-copy floor). Recorded, not
  dropped.
- **The `flatten` row is chunks-bound.** Native flatten is correct but the row needs native String `chunks`
  to clear. Pair chunks + flatten next session rather than re-measuring flatten alone.
- **The nested-block tail (groupBy/window/chunks/zip) needs variable-size nested String blocks** — the hard
  core of A; `filter`/`partition` were the only native bodies already on the generic String-correct
  get/append primitives.
