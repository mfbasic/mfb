Every completed bug in `bugs/completed/` was audited for a valid, active, real
regression test, verifying the actual test on disk rather than trusting each
doc's "Regression Test:" claim. This plan closes the gaps that audit found: it
adds a `tests/*` regression test for every completed bug that has none (Phase 1),
adds a `tests/*` integration fixture for every bug whose only guard is a `src/**`
unit test (Phase 2), and formally confirms the bugs for which a regression test
is not the appropriate guard (Phase 3).

The single behavioral outcome: after this plan, every completed bug either (a)
has a `tests/*` test that goes RED when the fix is reverted, or (b) is recorded
in Phase 3 with a verified reason why a `tests/*` test is not the right guard.

References:

- `.ai/testing-gates.md` — fixture authoring, golden generation, artifact-gate
  and byte-identity mechanics (READ FIRST — the whole execution recipe is here).
- `AGENTS.md` — "Never edit a test/golden to pass"; full `cargo test`, never one
  module; a claim is measured or a guess.
- `scripts/test-accept.sh` / `scripts/sync-goldens.sh` — the acceptance harness
  and golden refresh; every dir with a `project.json` is a test at any depth.
- `scripts/artifact-gate.sh` — codegen byte-identity gate (its `checked` count
  changes when byte-identity goldens are added).
- Each bug's own `bugs/completed/bug-NN-*.md` — the root cause and the exact
  behavior a new test must exercise.

## 1. Goal

- Every bug in `bugs/completed/` (429 docs) has a `tests/*` regression test, OR
  is listed in Phase 3 with a verified reason a `tests/*` test is inappropriate.
- Each new test is proven to actually guard the fix: it goes RED against a
  compiler with the fix reverted (or, for a codegen-inspection `.rs`/golden test,
  the asserted bytes/shape differ pre-fix).

### Non-goals (explicit constraints)

- Do NOT modify any existing passing test/golden to make it fit; add new tests.
  (`AGENTS.md`: never edit a test/golden to pass until proven wrong.)
- Do NOT re-open or re-fix the bugs themselves — the fixes are already landed and
  verified in the audit. This plan adds *coverage only*. If a new test reveals a
  fix is actually absent/wrong, that is a bug to file (`write-bug`), not silently
  patch here.
- Do NOT delete the `src/**` unit tests that already guard the Phase-2 bugs; the
  new `tests/*` fixture is additive integration coverage.
- Do NOT weaken the artifact-gate `checked` count; when a new byte-identity
  golden is added, update the gate's expected counts deliberately.

### Verified properties

- A fixture is any directory containing `project.json`; the harness discovers it
  at any depth (`scripts/test-accept.sh` "Every directory holding a project.json
  is a test"). A run-and-diff fixture carries `golden/{ast,ir,build.log}` plus a
  `<pkg>.run` trigger; its stdout is captured into `build.log` (the compared
  file). Verified against `tests/rt-behavior/collections/bug142_foreach_inplace_append`.
- `sync-goldens.sh` only REFRESHES existing golden files and never creates them,
  and never touches `.run` — a new fixture needs placeholder golden files created
  first (`.ai/testing-gates.md`).
- Compiler unit tests live in the **bin** target (`cargo test --bin mfb`); there
  is no `src/lib.rs`. `cargo test --lib` runs only the `mfb_repository` sub-crate.

## 3. Design Overview

This is NOT a byte-identity refactor plan — it ADDS behavioral coverage, so the
gate is "the new test goes RED without the fix", not "bytes unchanged". The only
byte-identity concern is that adding byte-identity/`.ncodesum` goldens changes
the artifact-gate `checked` count, which must be updated deliberately.

Pick the test shape per bug from its class (the audit evidence names the fixed
file, which tells you the shape):

1. **Runtime-behavioral bug** (wrong output, leak, crash, hang, UAF) →
   `tests/rt-behavior/<area>/<name>/` run fixture: `project.json` + `src/main.mfb`
   that exercises the bug + `golden/{ast,ir,build.log,<name>.run}`. Seed goldens
   with the RELEASE mfb (`sync-goldens.sh target/release/mfb <name>`) so output is
   deterministic (no perf table).
2. **Expected-error bug** (should trap / reject at runtime) →
   `tests/rt-error/<area>/<name>-rt/` fixture asserting the error output.
3. **Compile-time diagnostic / rejection bug** → `tests/syntax/<area>/<name>-{valid,invalid}/`
   (needs a `.mfp`/`.info`/`.run` golden to force the full `mfb build` so a
   package-emit-time diagnostic is actually reached — see `.ai/testing-gates.md`).
4. **Codegen-shape bug not reachable from a runtime program** (register clobber,
   encoder byte, ABI) → a `tests/*.rs` integration test that builds a fixture and
   inspects the `.ncode`/objdump, mirroring existing `tests/rt_*` and
   `tests/codegen_*` files. Only use this when a black-box runtime fixture cannot
   observe the bug.

**Per-bug workflow (the checkable unit):**
1. Read `bugs/completed/bug-NN-*.md`; identify the exact behavior the fix changed.
2. Author the smallest fixture/test that exercises it.
3. Prove it guards the fix: revert the fix locally (`git stash`-style scratch, or
   check the pre-fix behavior per the doc) and confirm the test goes RED; restore.
4. Seed/generate goldens (release mfb for rt-behavior); run
   `test-accept.sh target/release/mfb <name>` green.
5. Commit the fixture referencing the bug number in the fixture name
   (`bugNN_<slug>` convention) so future audits find it by number.

### Rejected alternatives

- *Auto-generating fixtures in bulk from the bug docs* — rejected: many docs
  describe the fix, not a black-box repro; each needs a hand-authored program
  that actually triggers the path. A generated stub that compiles but doesn't
  exercise the bug is exactly the vacuous test the audit flagged (bug-231).
- *Adding `#[ignore]` placeholder tests* — rejected: an inactive test is not
  coverage (`AGENTS.md` production-ready only).
