# OS Environment & Introspection (os)

The `os` package is the program's window onto the host process: it reads, tests,
sets, unsets, and enumerates environment variables, and reports read-only facts
about the running process and the build platform. Every call is a thin
compiler-owned runtime helper wrapping a libc primitive (or, for `os::name` /
`os::arch`, a compile-time constant baked in with no host call at all). There is
no MFBASIC source package behind `os` and no resource handle — every result is
an ordinary owned value. `os::sleep` is the one call that can *block*, and the one
whose behavior depends on which thread runs it. `os` is built in, so `IMPORT os` needs no manifest
dependency. [[src/codegen/builtins/os/mod.rs:register]]

This topic specifies the **model** — the read/mutate/snapshot semantics of the
environment, the argument-vector and platform-constant rules of the
introspection calls, the OS seam each maps onto, and the error and concurrency
model. The per-function signatures, overloads, and examples are owned by
`./mfb man os`.

## Type and marshalling model

Every argument and every result is a plain value: environment names and values
are UTF-8 `String`s, presence is a `Boolean`, `os::pid`/`os::cpuCount` are
`Integer`, the environment snapshot is a `Map OF String TO String`, and the
argument vector is a `List OF String`. [[src/codegen/builtins/os/func_args.rs:register]]

The host C library requires NUL-terminated strings. An MFBASIC `String` block
already is one — its bytes at `+8` end in a NUL — so each `String` **argument** is
handed to the libc call as a pointer into the caller's own block, with no copy and
nothing to release (plan-146-F; before it, every argument was copied into a fresh
`len + 1` arena buffer the helper freed at its exit label). Each `String`
**result** is still copied out of the host's buffer into a fresh owned arena
`String`, since the host's storage is not the program's to keep.

Reading the argument as a C string is why a variable **name** must be non-empty
and, for a name, free of `=` — the host uses `=` to separate a name from its
value. A name or value carrying an embedded NUL reaches the host truncated at that
NUL, the same as when the bytes were copied (the copy copied the NUL too); the
general rule is in `mfb spec` §"Lexical structure". The `os::getEnvOr` **fallback**
is a result, not an argument: it is copied by its stored byte length rather than by
NUL scan, so an embedded NUL there is preserved verbatim.
[[src/codegen/builtins/os/gen_shared.rs:borrow_cstring]]

## Environment: read, mutate, snapshot

The environment is process-global mutable state inherited from the host at
startup. `os` exposes it through three kinds of operation.

### Reads (getEnv, getEnvOr, hasEnv)

All three observe the **live** environment: they reflect both variables inherited
from the host and any change an earlier `os::setEnv` / `os::unsetEnv` made in the
same process. Each reduces to the host `getenv`; they differ only in how they
report absence.

| Call | Result | On a missing variable |
| --- | --- | --- |
| `os::getEnv` | `String` | **raises** `ErrNotFound` |
| `os::getEnvOr` | `String` | returns the caller's `fallback` (never raises) |
| `os::hasEnv` | `Boolean` | returns `FALSE` (never raises) |

The split exists so a program can decide whether absence is an error.
Critically, a variable **set to the empty string counts as present**: `getenv`
returns a non-NULL pointer to an empty string, so `os::hasEnv` reports `TRUE` and
`os::getEnv` returns `""` rather than raising. Only `os::getEnv` and `os::hasEnv`
can distinguish "set to empty" from "unset"; through `os::getEnvOr` an unset
variable and one set to `""` are indistinguishable, because both funnel to the
returned/`fallback` string. [[src/codegen/builtins/os/gen_env.rs:lower_get_env]] [[src/codegen/builtins/os/func_has_env.rs:lower_has_env]]

### Mutations (setEnv, unsetEnv)

Both are SUBs returning `Nothing`; both mutate the process-global environment and
are visible to every later read in the same process and inherited by child
processes spawned afterward.

* `os::setEnv(name, value)` maps to `setenv(name, value, 1)` — it **overwrites**
  any existing value. The host rejects an empty name or a name containing `=`
  (`errno = EINVAL`); the helper distinguishes that from an out-of-memory failure
  by reading `errno`, raising `ErrInvalidArgument` for the former and
  `ErrOutOfMemory` for `ENOMEM`. [[src/codegen/builtins/os/func_set_env.rs:lower_set_env]]
* `os::unsetEnv(name)` maps to `unsetenv(name)` and is **idempotent**: removing a
  variable that is not set is a no-op, not an error, so any return is treated as
  success. Afterward `os::hasEnv(name)` is `FALSE` and `os::getEnv(name)` raises
  `ErrNotFound`. [[src/codegen/builtins/os/func_unset_env.rs:lower_unset_env]]

### Snapshot (environ)

`os::environ()` returns a `Map OF String TO String` built by walking the host
environment array (the `NAME=VALUE` C-string vector) in two passes: one to size
the arena map, one to fill it. Each entry splits at its **first** `=` — the text
before it is the key and everything after it, *including any further `=`*, is the
value (so a `PATH`-like or `LS_COLORS`-like value keeps its embedded `=`). An
entry with no `=` at all maps its whole text to an **empty-string** value. On the
rare host that lists a name twice, the map keeps one entry for that key.
[[src/codegen/builtins/os/func_environ.rs:lower_environ]]

The returned map is an ordinary owned value **captured at the moment of the
call** — a snapshot, not a live view. A later `os::setEnv` / `os::unsetEnv` does
not change an already-returned map; re-read with a fresh `os::environ()` to
observe subsequent mutation. Like any `Map`, it is unordered.

### Concurrency

`getenv`/`setenv`/`unsetenv` are the classic non-reentrant trio: a reader must
not walk the environment array while a writer relocates or frees it. The runtime
therefore serializes **all** `os` environment (and passwd) access through one
process-global mutex. The readers (`os::getEnv`, `os::getEnvOr`, `os::hasEnv`,
`os::environ`, `os::userName`) hold it across both the libc call and the
copy-out-into-arena; the writers (`os::setEnv`, `os::unsetEnv`) hold it across the
mutation — so an `os` reader in one `thread::` worker never observes a
half-relocated environment while another worker's `os::setEnv` runs. A
single-threaded program pays only one uncontended lock/unlock per call. The lock
covers `os` calls among themselves; it cannot guard a raw `getenv`/`setenv`
reached through a native `LINK` outside the package. [[src/codegen/builtins/os/gen_shared.rs:OS_ENV_LOCK_SYMBOL]]

## Process & platform introspection

The remaining calls are all nullary and read-only. They fall into three groups by
where their answer comes from.

### Build-target constants (name, arch)

`os::name` and `os::arch` are **compile-time constants** selected by the build
target — the binary is built for exactly one target, so each is materialized
directly into a fresh owned `String` with no host call and cannot fail.

| Call | Value set | Source |
| --- | --- | --- |
| `os::name` | `"macos"` or `"linux"` (the target family) | target triple prefix |
| `os::arch` | `"aarch64"`, `"x86_64"`, or `"riscv64"` | target triple suffix |

Because they are fixed per build, both are stable across every run of the same
binary. [[src/codegen/builtins/os/gen_shared.rs:os_family]] [[src/codegen/builtins/os/gen_shared.rs:os_arch]]

### Never-failing host facts (pid, cpuCount)

* `os::pid()` returns the process id as an `Integer` via `getpid` — a positive
  value, stable for the life of the process, identical on every call within one
  process. It cannot fail. [[src/codegen/builtins/os/func_pid.rs:lower_pid]]
* `os::cpuCount()` returns the number of online logical CPUs via
  `sysconf(_SC_NPROCESSORS_ONLN)`, **clamped to a minimum of 1** so a caller
  always gets a usable count even when the host returns `-1`/`0` for an
  indeterminate answer. It cannot fail; use it to size a `thread::` worker pool.
  [[src/codegen/builtins/os/func_cpu_count.rs:lower_cpu_count]]

### The argument vector (args and prog)

`os::args()` returns the program's command-line arguments as a `List OF String`,
**excluding the program name**: element 0 is the first *real* argument, not the
executable. A program invoked with no arguments returns an empty list. The
arguments are captured once at program startup into two runtime globals the entry
code fills before any user code runs, so `os::args` reflects the invocation
regardless of where it is called; each element is copied out into an owned
`String`. Every argument is validated as UTF-8 before it is copied; a malformed
host byte sequence raises `ErrEncoding` and no invalid `String` is constructed.
[[src/codegen/builtins/os/func_args.rs:lower_args]] [[src/codegen/builtins/os/gen_shared.rs:OS_ARGV_GLOBAL_SYMBOL]]

`os::prog()` returns the program-name element, `argv[0]`, exactly as it was
supplied for this invocation. It can therefore differ from `os::executablePath()`:
the former preserves a relative path, symlink, or launcher spelling, while the
latter is the resolved absolute executable path. It applies the same UTF-8
boundary and raises `ErrEncoding` for malformed host bytes.
[[src/codegen/builtins/os/func_prog.rs:lower_prog]]

### May-fail host lookups (hostName, userName, executablePath)

Three `String`-returning calls query host state that can be unavailable, and each
raises `ErrUnsupported` (`77050007`) when the lookup cannot produce a value.

| Call | Host mechanism | `ErrUnsupported` when |
| --- | --- | --- |
| `os::hostName` | `gethostname` into a fixed buffer | the host cannot supply its name |
| `os::userName` | `getpwuid(getuid())->pw_name` | the effective uid has no passwd entry (e.g. a bare container uid) |
| `os::executablePath` | macOS `_NSGetExecutablePath`; Linux `readlink("/proc/self/exe")`; Windows `GetModuleFileNameW` | the host cannot determine the path |

`os::userName` resolves through the passwd database rather than the controlling
terminal, so it works without a login session (for example under a service
manager); its lookup shares the same process-global lock as the environment
readers, because `getpwuid` returns a pointer into a static buffer a concurrent
lookup could overwrite mid-copy. `os::executablePath` on Linux uses the byte
count `readlink` returns (that call does not NUL-terminate) and yields the
absolute, symlink-resolved path. [[src/codegen/builtins/os/func_host_name.rs:lower_host_name]] [[src/codegen/builtins/os/func_user_name.rs:lower_user_name]] [[src/codegen/builtins/os/func_executable_path.rs:lower_executable_path]]

### Build resources (appResourcePath)

`os::appResourcePath(relative As String = "") As String` returns the **absolute** on-disk
path of a resource the build copied out of the project's manifest `resources`
section (see `./mfb spec tooling project-manifest`). The same call resolves
correctly for every build shape because the base directory is derived at runtime
from the running executable's own path and a build-mode offset baked into the
binary:

| Build | Executable path | Resource base |
| --- | --- | --- |
| console | `…/build/<name>` | the executable's directory (`…/build`) |
| macOS `--app` | `…/Contents/MacOS/<name>` | `…/Contents/Resources` |
| Linux `--app` | `…/usr/bin/<name>` | `…/usr/share/<name>` |
| Windows `--app` | `…\build\<name>.exe` | the executable's directory (`…\build`) |

**Every native target supports the call**, including `windows-x86_64` — the
Windows base comes from `GetModuleFileNameW`, exactly as `os::executablePath`
does.

The result is `<base>/<relative>`, or `<base>` itself when `relative` is empty or
omitted — the joining `/` is emitted only for a non-empty `relative`, so the bare
base carries no trailing `/`. The in-place self-update arm
(`s = os::appResourcePath(s)`) copies one byte less of its cached `<base>/`
prefix for an empty `s` to agree.
[[src/codegen/builtins/os/func_app_resource_path.rs:lower_app_resource_path]]
[[src/codegen/collection/assign/string_self_update.rs:emit_app_resource_prefix]]
It is an absolute path with no `..` segments, so it
opens with `fs::open` regardless of the working directory — including a macOS
`.app` launched from Finder or a mounted `.AppImage`. Resolution reads only the
executable's own path (`/proc/self/exe` on Linux, `_NSGetExecutablePath` on
macOS, `GetModuleFileNameW` on Windows); it never consults `$APPDIR` or any
other environment variable.

The separator rules follow the rest of the path vocabulary. The base carries
whatever the host produced — `/` on macOS and Linux, `\` on Windows
(`C:\proj\build`) — and `<base>` and `<relative>` are joined with `/` on every
target, the same byte `fs::pathJoin` uses. A Windows result is therefore
`C:\proj\build/song.ogg`, which every Win32 path API accepts, and
`strings::endsWith(p, "/song.ogg")` holds on every target.

Two failures are catchable with `TRAP`. When the executable path cannot be
acquired (the same condition `os::executablePath` handles) the call raises
`ErrUnsupported` (`77050007`). When `relative` contains a `.` or `..` **path
component** it raises `ErrInvalidPath` (`77030002`) — a resource path must not
navigate out of the base. A dot *inside* a filename (`song.ogg`, `..foo`,
`a..b`) is fine; only a whole component that is exactly `.` or `..` is rejected.
A component boundary is `/` on every target and **also** `\` on Windows, where
`\` is a directory separator to every Win32 API — so `..\secret` is refused
there for the same reason `../secret` is. A leading `/` in `relative` is left
as-is (it collapses harmlessly under the base).
[[src/codegen/builtins/os/func_app_resource_path.rs:lower_app_resource_path]]

### Per-user app directories (appDataPath, appCachePath)

`os::appDataPath(relative As String = "") As String` and
`os::appCachePath(relative As String = "") As String` return the directory the
host designates for this program's per-user data and regenerable cache, with
the module (project) name appended — the same name in console and app builds,
so every build of a project shares one directory:

| Target | `appDataPath` base | `appCachePath` base |
| --- | --- | --- |
| macOS | `<home>/Library/Application Support/<name>` | `<home>/Library/Caches/<name>` |
| Linux (glibc, musl, AppImage) | `$XDG_DATA_HOME/<name>`, else `<home>/.local/share/<name>` | `$XDG_CACHE_HOME/<name>`, else `<home>/.cache/<name>` |
| Windows | `FOLDERID_RoamingAppData` `/<name>` | `FOLDERID_LocalAppData` `/<name>` |

`<home>` is `$HOME` when it is set and non-empty, else
`getpwuid(getuid())->pw_dir` (`pw_dir` is at offset 48 in macOS's
`struct passwd`, 32 in glibc's and musl's); with neither, the call raises
`ErrUnsupported`. An `XDG_*` value is used only when non-empty and absolute
(starts with `/`) — the XDG Base Directory specification says a relative value
is invalid and ignored. Trailing `/` bytes of an environment- or
`passwd`-derived base are dropped (a lone `/` stays).
[[src/codegen/builtins/os/gen_host_paths.rs:emit_posix_home_base]]
[[src/codegen/builtins/os/gen_host_paths.rs:emit_posix_env_abs_base]]
[[src/codegen/builtins/os/gen_host_paths.rs:lower_host_dir]]

On Windows the base is `SHGetKnownFolderPath` for the folder's `KNOWNFOLDERID`,
marshalled to UTF-8; it keeps the host's `\` separators and the joins use `/`,
as for `appResourcePath`. The system's wide buffer is `CoTaskMemFree`d on every
path, and a path whose UTF-8 does not fit the 8 KiB conversion buffer fails the
call (`ErrUnsupported`) rather than being truncated.
[[src/target/win_x86_64/code.rs:emit_known_folder_query]]

The result is `<base>` for an empty `relative` and `<base>/<relative>` otherwise,
with the same `.`/`..` component rejection (`ErrInvalidPath`) as
`appResourcePath`. Nothing is created and nothing is checked for existence. The
POSIX lookup runs under the env/pwd lock (`OS_ENV_LOCK_CALLS`): `getenv`'s
pointer is into `environ`, which a concurrent `os::setEnv` may relocate, and
`getpwuid`'s into a static record. The lock is taken before `relative` is
validated, so every exit releases a lock it holds.
[[src/codegen/builtins/os/gen_shared.rs:OS_ENV_LOCK_CALLS]]

A sandboxed macOS app has `$HOME` set to its container, so both calls resolve
inside the container; that is where a sandboxed app is permitted to write.

**In-place self-update.** `s = os::appDataPath(s)` (and `appCachePath`) lowers
in place (`GrowKind::HostPath`). The base is re-read on every statement — never
cached, so an `os::setEnv("HOME", …)` between two statements moves the next
result exactly as it moves the copying call's — through the member's
internal, non-allocating `appDataPathBase`/`appCachePathBase` helper, which
writes the base into the function's self-update scratch and returns its length
(-1 when the host cannot answer). The arm therefore allocates only when that
scratch grows. On Windows the helper converts the known folder straight into
the scratch (`CodegenPlatform::emit_known_folder_into`) instead of through an
arena buffer.
[[src/codegen/collection/assign/string_self_update.rs:HOST_PATH_ARM_MEMBERS]]
[[src/target/win_x86_64/code.rs:emit_known_folder_into_query]]

### User directories (userHomePath, userDocumentsPath)

`os::userHomePath(relative As String = "") As String` and
`os::userDocumentsPath(relative As String = "") As String` return the user's home
and Documents folders — not app-scoped, so nothing is appended:

| Target | `userHomePath` base | `userDocumentsPath` base |
| --- | --- | --- |
| macOS | `<home>` | `<home>/Documents` |
| Linux | `<home>` | `XDG_DOCUMENTS_DIR` from `<config>/user-dirs.dirs`, else `<home>/Documents` |
| Windows | `FOLDERID_Profile` | `FOLDERID_Documents` (follows OneDrive / folder redirection) |

`<home>` is the `appDataPath` home rule (`$HOME` when non-empty, else
`pw_dir`, trailing `/` trimmed); `<config>` is `$XDG_CONFIG_HOME` when non-empty
and absolute, else `<home>/.config`. Windows reads neither `HOME` nor the file.
When the base is the root `/`, a joined `relative` or suffix does not double the
separator (`/a`, not `//a`).
[[src/codegen/builtins/os/gen_host_paths.rs:emit_posix_host_dir]]

The Linux `user-dirs.dirs` parse mirrors GLib's `load_user_special_dirs` so an MFB
program and a GTK application agree: per line, leading blanks, the literal
`XDG_DOCUMENTS_DIR`, blanks, `=`, blanks, `"`; then `$HOME` (home-relative) or
`/` (absolute), anything else voids the line; the value runs to the **last** `"`
on the line, loses one trailing `/`, and a later valid line replaces an earlier
one. A home-relative value is joined as `home ++ ("/" unless it starts with one)
++ value`. The file is read in 4 KiB chunks by a byte state machine whose state
survives the refill (no file-size cap), `read` is retried on `EINTR`, and the
descriptor is opened `O_CLOEXEC`. Three deliberate differences from GLib (all
measured against GLib on a Debian box): a value longer than 4096 bytes
(`PATH_MAX`) is ignored rather than used; an absolute value that is empty after
the trailing-`/` drop (`"/"`) is ignored rather than yielding an empty path; and a
relative `XDG_CONFIG_HOME` is ignored as the XDG Base Directory specification
requires, where GLib uses it relative to the working directory.
[[src/codegen/builtins/os/gen_user_dirs.rs:emit_linux_user_dirs_documents]]

Both calls share the `appDataPath` machinery: the env/pwd lock, the
`ErrUnsupported` / `ErrInvalidPath` errors, no creation and no existence check,
the in-place `GrowKind::HostPath` arm with its non-allocating
`userHomePathBase` / `userDocumentsPathBase` helpers, and — sandboxed on macOS —
the container's folders. On Windows the `*Base` helper's contract ("written
exactly when the returned length is ≤ the capacity") needs one extra byte for the
known-folder conversion's NUL when nothing follows the folder, so a fill that
did not fit reports `length + 1`.
[[src/codegen/builtins/os/gen_host_paths.rs:lower_host_dir]]

The macOS `.app` `Info.plist` carries `NSDocumentsFolderUsageDescription` ("<name>
reads and writes files in your Documents folder."), the text of the privacy
prompt macOS shows the first time the app touches the Documents folder. It is
unconditional — the link stage does not see which calls the program makes.
[[src/os/macos/link/mod.rs:app_info_plist]]

## Blocking the calling thread (sleep)

`os::sleep(ms)` blocks the *calling* thread for at least `ms` milliseconds and
returns `Nothing`. It is the language's only sleep, and it takes no thread handle:
the same call is correct on the program's main thread and inside a `thread::start`
worker, because the behavior is chosen from the running context rather than from an
argument.

Following the `ms` convention, `0` returns immediately, a positive `ms` blocks for
at least that long, and a negative `ms` raises `ErrInvalidArgument` before any wait.
The unit is milliseconds — the unit every `thread::` timeout uses, and the honest
cross-target granularity floor (it is what Win32 `Sleep` speaks). There is no
sub-millisecond form; measure finer intervals with `datetime::monotonicNanos`.

On the main thread the delay is plain and **uninterruptible**: it has no wakeup
path, and a signal that cuts the underlying wait short re-enters it, so the call
never returns early.

Inside a worker the same call is a **cancellation point**: the sleep wakes early and
fails with `ErrInterrupted` when the parent requests cancellation
(`thread::cancel`, or dropping the parent handle), matching `thread::receive` and
`thread::send` on a worker handle. Its deadline is absolute, so an inbound
`thread::send` arriving mid-sleep does not shorten it. How the two are told apart —
the thread control block the worker trampoline publishes in its arena state — is
specified in `./mfb spec threading` and `./mfb spec memory arenas`; a program never
sees it. `ErrInterrupted` is declared on **every** `os::sleep`, because a shared
`FUNC` may be called from the main thread and from a worker and the compiler cannot
localize the error surface; it can only ever be raised in a worker.

## The OS seam

Each `os` call — except the two build-target constants — lowers to a small
runtime helper that wraps one or two libc primitives and returns through the
standard four-register fallible result form (an infallible call still sets the OK
tag and puts its value in the result register). The seam is entirely libc:
`getenv` (reads and presence), `setenv`/`unsetenv` (mutation), the platform
`environ` array accessor (snapshot), `getpid`, `sysconf`, `gethostname`,
`getuid`/`getpwuid`, and the platform executable-path primitive (shared by
`os::executablePath` and `os::appResourcePath`). `os::name` and
`os::arch` bypass the seam entirely — they are constants chosen from the target
triple at build time. `os::args` reads the entry-captured argument globals rather
than a syscall. Every result — `String`, `Boolean`, `Integer`, `List`, `Map` —
is built directly in the arena as an owned value, so nothing here holds a resource
handle or needs a `CLOSE`. [[src/codegen/builtins/os/gen_paths.rs:emit_executable_path_into]]

## Error model

| Code | Name | Raised by |
| --- | --- | --- |
| `77050004` | `ErrNotFound` | `os::getEnv` on an unset variable |
| `77050002` | `ErrInvalidArgument` | `os::setEnv` on an empty name or a name containing `=` |
| `77050007` | `ErrUnsupported` | `os::hostName` / `os::userName` / `os::executablePath` / `os::appResourcePath` / `os::appDataPath` / `os::appCachePath` / `os::userHomePath` / `os::userDocumentsPath` when the host lookup fails |
| `77030002` | `ErrInvalidPath` | `os::appResourcePath` / `os::appDataPath` / `os::appCachePath` / `os::userHomePath` / `os::userDocumentsPath` when `relative` contains a `.` or `..` path component |
| `77010001` | `ErrOutOfMemory` | any call, when the arena cannot allocate the returned value (or `os::setEnv` its stored variable) |
| `77050002` | `ErrInvalidArgument` | `os::sleep` on a negative `ms` |
| `77050009` | `ErrInterrupted` | `os::sleep` inside a worker, when the parent requests cancellation |

`os::getEnvOr`, `os::hasEnv`, `os::unsetEnv`, `os::environ`, `os::args`,
`os::name`, `os::arch`, `os::pid`, and `os::cpuCount` have no failure mode of
their own beyond a possible `ErrOutOfMemory` on the allocating ones
(`os::getEnvOr`, `os::environ`, `os::args`); `os::hasEnv`, `os::unsetEnv`,
`os::name`, `os::arch`, `os::pid`, and `os::cpuCount` never raise at all. A raised
error propagates like any fallible call and can be caught with `TRAP`.
